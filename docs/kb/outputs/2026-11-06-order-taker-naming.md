# Order Taker naming and the stored order source

The owner asked to rename POS and Manual POS to Order Taker and Manual Order Taker. In the current code `Manual POS` is stored in `public.orders.source`. The order creation RPC writes it, and the database check constraint accepts it alongside `QR Order`. The frontend already translates `Manual POS` into `Order Taker` for display, while dashboard aggregation and source filters use the stored string. [Order schema and check](../../../supabase/migrations/20261020143115_remote_schema.sql#L227) · [Manual order writer](../../../supabase/migrations/20261020143115_remote_schema.sql#L910) · [Display label](../../../src/utils/orderUtils.js) · [Dashboard aggregation](../../../src/services/dashboardService.js#L93) · [Source filter](../../../src/pages/superAdmin/SuperAdminOrdersPage.jsx#L23)

A display rename can keep the stored value stable. A rename in SQL Editor results requires a coordinated migration of the stored value, the source constraint, and the writer, plus frontend compatibility and a plan for both databases and persisted sync snapshots. Rewriting only existing rows would not change new order creation or reporting. The requested scope remains to be confirmed. No rename was applied.
